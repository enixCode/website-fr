Introduction

Ce document présente le développement d'un package Go simple à l'intérieur d'un module et introduit l'outil go, la méthode standard pour récupérer, compiler et installer des modules, packages et commandes Go.

Organisation du code

Les programmes Go sont organisés en packages. Un package est un ensemble de fichiers source dans le même répertoire, compilés ensemble. Les fonctions, types, variables et constantes définis dans un fichier source sont visibles par tous les autres fichiers source du même package.

Un repository contient un ou plusieurs modules. Un module est un ensemble de packages Go liés, publiés ensemble. Un repository Go ne contient généralement qu'un seul module, situé à la racine du repository. Un fichier nommé go.mod y déclare le module path : le préfixe d'import path pour tous les packages du module. Le module contient les packages dans le répertoire contenant son fichier go.mod ainsi que les sous-répertoires de ce répertoire, jusqu'au prochain sous-répertoire contenant un autre fichier go.mod (s'il existe).

Note : tu n'as pas besoin de publier ton code dans un repository distant avant de le compiler. Un module peut être défini localement sans appartenir à un repository. C'est cependant une bonne habitude d'organiser ton code comme si tu allais le publier un jour.

Le path de chaque module ne sert pas seulement de préfixe d'import path pour ses packages, il indique aussi où la commande go doit aller le télécharger. Par exemple, pour télécharger le module golang.org/x/tools, la commande go consultera le repository indiqué par https://golang.org/x/tools (décrit plus en détail ici).

Un import path est une chaîne utilisée pour importer un package. Le import path d'un package est son module path joint à son sous-répertoire dans le module. Par exemple, le module github.com/google/go-cmp contient un package dans le répertoire cmp/. Le import path de ce package est github.com/google/go-cmp/cmp. Les packages de la bibliothèque standard n'ont pas de préfixe de module path.

Ton premier programme

Pour compiler et exécuter un programme simple, choisis d'abord un module path (nous utiliserons example/user/hello) et crée un fichier go.mod qui le déclare : 

$ mkdir hello # Ou clone le dépôt s'il existe déjà dans un système de contrôle de version.
$ cd hello
$ go mod init example/user/hello
go: creating new go.mod: module example/user/hello
$ cat go.mod
module example/user/hello

go 1.16
$

La première instruction d'un fichier source Go doit être package name. Les commandes exécutables doivent toujours utiliser package main.

Ensuite, crée un fichier nommé hello.go dans ce répertoire, contenant le code Go suivant : 

package main

import "fmt"

func main() {
    fmt.Println("Hello, world.")
}

Tu peux maintenant compiler et installer ce programme avec l'outil go : 

$ go install example/user/hello
$

Cette commande compile la commande hello et produit un binaire exécutable. Elle installe ensuite ce binaire sous $HOME/go/bin/hello (ou, sous Windows, %USERPROFILE%\go\bin\hello.exe).

Le répertoire d'installation est contrôlé par les variables d'environnement GOPATH et GOBIN. Si GOBIN est défini, les binaires sont installés dans ce répertoire. Si GOPATH est défini, les binaires sont installés dans le sous-répertoire bin du premier répertoire de la liste GOPATH. Sinon, les binaires sont installés dans le sous-répertoire bin du GOPATH par défaut ($HOME/go ou %USERPROFILE%\go).

Tu peux utiliser la commande go env pour définir de façon portable la valeur par défaut d'une variable d'environnement pour les futures commandes go : 

$ go env -w GOBIN=/somewhere/else/bin
$

Pour annuler une variable précédemment définie par go env -w, utilise go env -u : 

$ go env -u GOBIN
$

Les commandes comme go install s'appliquent dans le contexte du module contenant le répertoire de travail courant. Si le répertoire de travail n'est pas dans le module example/user/hello, go install peut échouer.

Pour plus de commodité, les commandes go acceptent des chemins relatifs au répertoire de travail et utilisent par défaut le package du répertoire de travail courant si aucun autre chemin n'est fourni. Ainsi, dans notre répertoire de travail, les commandes suivantes sont toutes équivalentes : 

$ go install example/user/hello

$ go install .

$ go install

Ensuite, exécutons le programme pour vérifier qu'il fonctionne. Pour plus de commodité, nous allons ajouter le répertoire d'installation à notre PATH afin de faciliter l'exécution des binaires : 

# Les utilisateurs Windows doivent consulter /wiki/SettingGOPATH
# pour configurer %PATH%.
$ export PATH=$PATH:$(dirname $(go list -f '{{"{{.Target}}"}}' .))
$ hello
Hello, world.
$

Si tu utilises un système de contrôle de version, c'est le bon moment pour initialiser un repository, ajouter les fichiers et effectuer ton premier commit. Cette étape est facultative : tu n'as pas besoin d'utiliser le contrôle de version pour écrire du code Go. 

$ git init
Initialized empty Git repository in /home/user/hello/.git/
$ git add go.mod hello.go
$ git commit -m "initial commit"
[master (root-commit) 0b4507d] initial commit
 1 file changed, 7 insertion(+)
 create mode 100644 go.mod hello.go
$

La commande go localise le repository contenant un module path donné en demandant l'URL HTTPS correspondante et en lisant les métadonnées intégrées dans la réponse HTML (voir go help importpath). De nombreux services d'hébergement fournissent déjà ces métadonnées pour les repositories contenant du code Go, donc le moyen le plus simple de rendre ton module disponible est généralement de faire correspondre son module path avec l'URL du repository.

Importer des packages de ton module

Écrivons un package morestrings et utilisons-le depuis le programme hello. Crée d'abord un répertoire pour le package nommé $HOME/hello/morestrings, puis un fichier nommé reverse.go dans ce répertoire avec le contenu suivant : 

// Package morestrings implements additional functions to manipulate UTF-8
// encoded strings, beyond what is provided in the standard "strings" package.
package morestrings

// ReverseRunes returns its argument string reversed rune-wise left to right.
func ReverseRunes(s string) string {
    r := []rune(s)
    for i, j := 0, len(r)-1; i < len(r)/2; i, j = i+1, j-1 {
        r[i], r[j] = r[j], r[i]
    }
    return string(r)
}

Comme notre fonction ReverseRunes commence par une lettre majuscule, elle est exportée et peut être utilisée dans d'autres packages qui importent notre package morestrings.

Vérifions que le package se compile avec go build : 

$ cd $HOME/hello/morestrings
$ go build
$

Cela ne produira pas de fichier de sortie. À la place, le package compilé est sauvegardé dans le cache de compilation local.

Après avoir vérifié que le package morestrings se compile, utilisons-le depuis le programme hello. Pour cela, modifie ton fichier original $HOME/hello/hello.go pour utiliser le package morestrings : 

package main

import (
    "fmt"

    "example/user/hello/morestrings"
)

func main() {
    fmt.Println(morestrings.ReverseRunes("!oG ,olleH"))
}

Installe le programme hello : 

$ go install example/user/hello

En exécutant la nouvelle version du programme, tu devrais voir un nouveau message inversé : 

$ hello
Hello, Go!

Importer des packages de modules distants

Un import path peut décrire comment obtenir le code source du package en utilisant un système de contrôle de version tel que Git ou Mercurial. L'outil go utilise cette propriété pour récupérer automatiquement les packages depuis des repositories distants. Par exemple, pour utiliser github.com/google/go-cmp/cmp dans ton programme : 

package main

import (
    "fmt"

    "example/user/hello/morestrings"
    "github.com/google/go-cmp/cmp"
)

func main() {
    fmt.Println(morestrings.ReverseRunes("!oG ,olleH"))
    fmt.Println(cmp.Diff("Hello World", "Hello Go"))
}

Maintenant que tu as une dépendance sur un module externe, tu dois télécharger ce module et enregistrer sa version dans ton fichier go.mod. La commande go mod tidy ajoute les dépendances manquantes pour les packages importés et supprime les dépendances sur les modules qui ne sont plus utilisés. 

$ go mod tidy
go: finding module for package github.com/google/go-cmp/cmp
go: found github.com/google/go-cmp/cmp in github.com/google/go-cmp v0.5.4
$ go install example/user/hello
$ hello
Hello, Go!
  string(
-     "Hello World",
+     "Hello Go",
  )
$ cat go.mod
module example/user/hello

go 1.16

require github.com/google/go-cmp v0.5.4
$

Les dépendances du module sont automatiquement téléchargées dans le sous-répertoire pkg/mod du répertoire indiqué par la variable d'environnement GOPATH. Le contenu téléchargé pour une version donnée d'un module est partagé entre tous les autres modules qui require cette version, donc la commande go marque ces fichiers et répertoires en lecture seule. Pour supprimer tous les modules téléchargés, tu peux passer le flag -modcache à go clean : 

$ go clean -modcache
$

Tests

Go dispose d'un framework de test léger composé de la commande go test et du package testing.

Tu écris un test en créant un fichier dont le nom se termine par _test.go et qui contient des fonctions nommées TestXXX avec la signature func (t *testing.T). Le framework de test exécute chaque fonction de ce type. Si la fonction appelle une fonction d'échec comme t.Error ou t.Fail, le test est considéré comme échoué.

Ajoute un test au package morestrings en créant le fichier $HOME/hello/morestrings/reverse_test.go contenant le code Go suivant. 

package morestrings

import "testing"

func TestReverseRunes(t *testing.T) {
    cases := []struct {
        in, want string
    }{
        {"Hello, world", "dlrow ,olleH"},
        {"Hello, 世界", "界世 ,olleH"},
        {"", ""},
    }
    for _, c := range cases {
        got := ReverseRunes(c.in)
        if got != c.want {
            t.Errorf("ReverseRunes(%q) == %q, want %q", c.in, got, c.want)
        }
    }
}

Exécute ensuite le test avec go test : 

$ cd $HOME/hello/morestrings
$ go test
PASS
ok  	example/user/hello/morestrings 0.165s
$

Exécute go help test et consulte la documentation du package testing pour plus de détails.
